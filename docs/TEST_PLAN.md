### 1.1 引擎离线验证（不依赖设备）

设备端的首次部署耗时较长，且难以逐项观察候选，因此额外提供宿主机验证：

```bash
# 1) 宿主机编译 librime（与 Android 同版本源码）
# 2) 编译验证程序
g++ -std=c++17 -O1 -o rime_probe tools/rime_probe.cc \
    -I$HOST_PREFIX/include -L$HOST_PREFIX/lib \
    -lrime -lopencc -lmarisa -lleveldb -lyaml-cpp -lboost_regex -lpthread -ldl \
    -Wl,-rpath,$HOST_PREFIX/lib
# 3) 用与 APK 完全相同的资源目录驱动引擎
./rime_probe <shared_dir> <user_dir>
```

`tools/rime_probe.cc` 与 `tools/rime_probe_en.cc` 会输出：部署结果、方案列表、
组合串、候选列表、翻页结果、简繁转换结果、最近候选的英文词、用户数据落盘结果。

## 2. 构建与初始化

- [ ] 干净环境下 Gradle 同步与构建成功
      判定：`scripts/build-apk.sh` 退出码 0，产出签名 APK
- [ ] APK 可安装、启动、卸载
      判定：`adb install` 成功；应用能启动；卸载后无残留进程
- [ ] 首次启动自动部署 Rime 资源，不要求用户手动导入
      判定：日志出现 `词库部署 → deploy: start / deploy: success`；主页底部显示「词库已就绪」
- [ ] 第二次启动不重复覆盖用户数据
      判定：第二次启动 `rime_user` 目录内 `userdb`、`user.yaml` 的修改时间不变
- [ ] 初始化失败有日志、可读提示和重试能力
      判定：制造失败（例如临时移走 `rime_shared/build`）后主页显示失败原因，「词库与语言 → 重新部署」可恢复

## 3. 系统输入法集成

- [ ] 系统设置可看到 IceType
      判定：系统设置 → 语言与输入法 → 管理键盘 中出现「IceType 雾凇输入法」
- [ ] 点击「启用输入法」能进入正确设置或给出可靠回退指引
      判定：优先进入 `ACTION_INPUT_METHOD_SETTINGS`；若系统无此页则显示手动路径卡片
- [ ] 点击「选择输入法」可调出系统输入法选择器
      判定：出现系统输入法切换弹窗
- [ ] 启用/选中状态能正确检测并随返回刷新
      判定：主页三种状态（未启用 / 已启用未选中 / 正在使用）与系统设置一致；从系统设置返回应用时状态自动刷新
- [ ] 输入法可在不同应用的文本框中正常使用
      判定：在浏览器地址栏、聊天应用、便签中均可输入

## 4. 输入能力

- [ ] 中文拼音、候选选择、空格上屏、退格和候选翻页正常
      判定：输入 `nihao` 首候选为「你好」；空格上屏；退格逐字符回退；`shi` 可翻到第 2 页
- [ ] 用户词频学习能持久化

- [ ] 英文候选能按配置出现，并验证 `h` 等前缀的候选效果
      判定：见第 6 节实测数据；`h` 的候选列表中存在 `he/hem/hen/...`，`hel` 中存在 `held/hell/help/hello`，
      `hello` 为首候选
- [ ] 中文/英文切换、符号、数字键盘正常
      判定：中英切换后布局与候选行为同步变化；符号键真实上屏并进入「最近使用」
- [ ] 搜索、网址、邮箱、数字、电话、密码等输入类型分别测试

## 7. 已知限制（不掩盖、不用假控件代替）

1. **首次部署耗时**：不打包预编译词库产物，首次启动需由 librime 编译一次词典。
   宿主机（8 核 aarch64）实测约 35 秒；设备端会更久，期间有进度提示与重试入口。
2. **英文候选排序**：雾凇方案默认把拼音候选排在英文之前，输入 `h` 时英文候选在第 9–12 页。
   应用提供「英文候选优先」开关（写入 `rime_ice.custom.yaml` 提升 `melt_eng` / `cn_en` 权重），
   实测可把 `hel` 的首屏候选变为英文词。
3. **表情搜索**：未提供搜索框。本地未建立可检索的表情索引，做了也只是无效入口。
4. **按键音音量**：Android 未提供按输入法调整该音效音量的公开接口，因此只提供开关，不提供音量滑块。
5. **数字/电话类输入框**：目前按 `EditorInfo` 识别并在日志中记录，但未自动切换到数字键盘
   （仅在用户手动切到数字键盘时使用）。
6. **语音输入**：未接入，因此键盘上不显示语音按钮（避免假按钮）。
7. **横屏**：布局会随宽度重新排布，但尚未在横屏下逐项校准视觉比例。
8. **双拼 / 九键（t9）方案**：资源已随 APK 一同部署并出现在方案列表中，但键盘尚未提供
   对应的双拼键位与九宫格布局，因此不能在应用内切换使用。
